A complete regex-based demonstration for recognizing the syntactic structure of web addresses. Inspect the pattern, try a URL, and see each component evaluated.

What is a URL?

A Uniform Resource Locator (URL) identifies the location of a resource on the web. Its structured parts tell a browser which protocol to use, which server to contact, and optionally which resource, query, or fragment to request. Applications often validate URL syntax before storing a link or processing a user-submitted address.

How regular expressions validate a URL

The pattern below describes the URL grammar adopted by this project. The ^ and $ anchors demand a full-string match. Parenthesized groups organize optional components; ? makes those groups optional. This validator intentionally supports http and https, conventional domains, and optional port, path, query, and fragment sections.

ACTUAL JAVASCRIPT REGEXP/i = case-insensitive
^https?:\/\/
Protocol
Accepts http:// or https:// at the start.
(?:[a-z0-9-]+\.)*
Subdomain
Allows zero or more labels such as www. or api..
[a-z0-9](?:[a-z0-9-]*[a-z0-9])?
Domain
A domain label begins and ends with an alphanumeric character.
\.[a-z]{2,}
Top-level domain
Requires a dot followed by a two-or-more-letter TLD, such as .com.
(?::\d{1,5})?
Port
Optionally permits a colon and one to five digits.
(?:\/[^\s?#]*)?
Path
Optionally matches a slash followed by path characters.
(?:\?[^\s#]*)?
Query
Optionally matches ? and a query string without whitespace.
(?:#[^\s]*)?$
Fragment
Optionally matches a # fragment and then reaches the end.
