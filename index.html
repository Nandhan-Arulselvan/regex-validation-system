01 / FOUNDATION

What is a Regular Expression?

A regular expression (regex) is a compact notation for describing a pattern of characters. Instead of listing every acceptable input, it defines the form an input must follow. A regex engine reads the pattern and determines whether a given string contains—or exactly matches—that form.

In theory, a regex describes a regular language: a set of strings that follow a particular rule. For example, the language described by ^[0-9]+$ contains every non-empty string made only of digits: 7, 42, and 2026.

For validation, we normally anchor a pattern to the beginning and end of the input. This prevents a valid-looking piece inside a larger invalid value from being accepted. Regex is useful because it is precise, fast for structured checks, and easy to reuse in forms, data cleaning, search, log analysis, and text filtering.

\d+one or more digits
[A-Z]one uppercase English letter
^[0-9]+$an input consisting entirely of digits

03 / THEORY

Regex and Finite Automata

The validators are practical examples of a core Models of Computation idea: regular expressions describe regular languages, and finite automata recognize those languages.

Regular languages

Languages formed by rules with finite, repeatable structure. URLs with a defined syntax and passwords satisfying a policy are treated as languages in this project.

NFA & DFA

An NFA may have several possible next states; a DFA has exactly one next state for each input symbol. Both recognize exactly the class of regular languages.

Acceptance

An automaton accepts when it finishes in an accepting state. Analogously, our JavaScript regex returns true when the complete input matches its pattern.

The finite-automata relationship is the theoretical foundation of regex. JavaScript engines have implementation-specific optimizations; this page does not claim they literally turn every JavaScript regex into a DFA.
